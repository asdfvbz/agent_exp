# 经验包

**解决的问题:空库检索不出任何东西,而没人愿意在早期往里写。**

通用型的坑(换任何项目都成立的那些)可以先打包发出去,让别人一装就有东西用。
这是"通用经验库"做不到的事 —— 项目私有的经验不可共享,所以那个方向永远逃不出冷启动。

## 结构

```
packs/<包名>/
├── README.md          # 第一行非标题文字会显示在 pack list 里
└── lessons/*.md       # 就是普通的经验文件,和 .exp/lessons/ 里的格式一样
```

## 用法

```bash
exp pack list                    # 看有哪些包
exp pack show seed               # 看一个包含什么
exp pack install seed            # 装到全局层(默认)
exp pack install seed --layer project
```

默认装到**全局层** —— 因为这些坑跨项目都用,装一次受益于所有项目。

## 写一个包

直接建目录、放 `.md` 就行,不用注册任何东西。一条经验一个文件,
frontmatter 的格式和 `exp add` 写出来的一样(frontmatter 里**不要**放计数器,
它们是本机遥测)。

**收录标准** —— 一条经验够格进经验包,要同时满足:

1. **跨项目成立** —— 不是"我们仓库的约定",是"任何仓库都这样"
2. **失败不吭声** —— 能立刻被测试/linter 发现的坑不需要经验库
3. **`fix` 可执行** —— 照着做能不能机械化地判断做没做到

三条里最容易被违反的是第二条。检查方法:**这个坑如果犯了,多久会知道?**
两秒就知道的,不该进来。

## 注意

装进来的经验 `status` 保持原样(`confirmed` / `hypothesis`)。
**别人的 `confirmed` 不等于在你的环境里 confirmed** ——
它们只是起点,在你自己的使用中积累的 `recurred` / `missed` 才是属于你的信号。
